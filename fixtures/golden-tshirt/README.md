# Golden T-Shirt v1

> **Synthetic test data. Not a size table, not a drafting norm, not a product specification.**
> Every measurement, proportion, ease value and tolerance used here was invented for this fixture.
> The domain review by a pattern maker or seamstress (test QEV-016) is **pending** (`v1/manifest.json` → `review.status: "pending"`), and nothing in this fixture claims that it has been done.

The Golden T-Shirt is the reference object of the standard: one simple, sewable T-shirt in two sizes and two material/fit configurations, with a change case. Paths in this README are relative to `v1/` unless stated otherwise. Implementations are compared with the expected results in `expected/` using the pinned tolerance profile `d2p:golden-tshirt-2d` `1.0.0` (status **provisional**, see `tolerance-profiles/`). The layout and the normative identifiers follow [`specifications/schema-catalog.md`](../../specifications/schema-catalog.md) §4.

## How the files are produced

Everything in `v1/` is generated by the reference oracle [`tools/oracle/golden-tshirt.mjs`](../../tools/oracle/README.md) (plain Node.js, no dependencies). Do not edit generated files by hand.

```bash
npm run oracle          # regenerate inputs/, expected/, negative/ and manifest.json
npm run oracle:check    # regenerate into a temporary directory, byte-compare, validate against the schemas
node tools/oracle/golden-tshirt.mjs --check --summary   # same check, plus seam lengths, fit results and tiling
```

`npm run check` and the CI workflow (`.github/workflows/ci.yml`) run `oracle:check` and `fixture:verify`, so a hand edit, a stale file or a changed external file (registry, tolerance profile, validation rules or profiles) fails CI until the fixture is regenerated and reviewed. A change of any generated content is a new fixture version.

The oracle is independent of any implementation: it evaluates the published `inputs/pattern-r1.json` with its own interpreter for the closed expression language and the feature types used, and it checks every point feature against a second, closed-form construction written in plain arithmetic. Both must agree to 1e-9 mm, otherwise nothing is written.

## Contents

| Path | Content |
|---|---|
| `inputs/` | project, artifact metadata, revision records, relationships, the six artifact content documents (pattern, grading rule set, size system, two fit profiles, garment measurement spec), four r1 evaluation requests, the change command and two r2 evaluation requests |
| `expected/evaluations/`, `expected/snapshots/` | per case: pattern evaluation and geometry snapshot (control points, notches, grainlines, bounding boxes, areas, interface and seam lengths) |
| `expected/fit/` | analytic fit evaluation reports (r1) |
| `expected/validation/` | `sample-cut` reports (r1), `1to1-print` reports and `export-1to1` gates for the two export cases |
| `expected/export/` | ExportScene2D and PrintJobSpec (A4, tiled, 100 mm control square) for size A and size B |
| `expected/change/` | pattern r2, its revision record and the command receipt |
| `negative/<name>/` | the defective documents of one negative fixture plus `case.json` (expected diagnostic) |
| `manifest.json` | every file with role, documentType and d2p-digest-v1 digest, external files, configurations, change case, review state, `fixtureDigest` |

A case is `<rev>-<sizeKey>-<configurationKey>`: `r1-size-a-regular-woven`, `r1-size-a-relaxed-knit`, `r1-size-b-regular-woven`, `r1-size-b-relaxed-knit`, `r2-size-a-regular-woven`, `r2-size-b-regular-woven`.

## Inputs

### Measurements (synthetic, non-normative)

Sizes are resolvable only as size system `art_golden-tshirt-size-system` @ `rev_golden-tshirt-size-system-r1` plus `sizeKey`. Every value is a `measurementValue` with `method: "size-table"`, `source.kind: "synthetic"` and a symmetric uncertainty. Definitions come from `d2p:measurement-definitions` `1.0.0`.

| Definition (input key) | size-a (label A) | size-b (label B) | uncertainty |
|---|---:|---:|---:|
| `d2p:body.chest-girth` (`chest-girth`) | 920 mm | 1040 mm | ± 5 mm |
| `d2p:body.waist-girth` (`waist-girth`) | 800 mm | 940 mm | ± 5 mm |
| `d2p:body.shoulder-width` (`shoulder-width`) | 420 mm | 460 mm | ± 5 mm |
| `d2p:body.arm-length` (`arm-length`) | 600 mm | 630 mm | ± 3 mm |
| `d2p:body.neck-girth` (`neck-girth`) | 370 mm | 400 mm | ± 5 mm |
| `d2p:body.back-length` (`back-length`) | 420 mm | 440 mm | ± 3 mm |

All six measurement inputs of the pattern are `required: true` and have no fallback.

### Material/fit configurations

| `configurationKey` | Fit profile | Chest ease rule `ease-chest` | `materialAssumptions` |
|---|---|---|---|
| `regular-woven` | `art_golden-tshirt-fit-profile-regular` r1, intent `d2p:regular` | wearing ease 100 mm | `{materialClass: woven}` |
| `relaxed-knit` | `art_golden-tshirt-fit-profile-relaxed` r1, intent `d2p:relaxed` | wearing ease 160 mm | `{materialClass: knit}` |

Under the measurement-input resolution rules of standard 1.0 (catalog §3.4), a fit profile and material assumptions do not enter the geometric evaluation. Geometry, control points and seam lengths are therefore **identical for both configurations of a size**, and the oracle asserts this (equal `geometryDigest`). The configurations differ in their fit evaluation: the garment measurement spec targets the body chest girth plus the configuration's ease (tolerance ± 10 mm) and the sleeve length `round(0.33 × arm length)` (tolerance ± 5 mm). With the pattern's `bust-ease` of 100 mm, the regular configuration is within tolerance and the relaxed configuration's chest girth is reported `outside-tolerance` (deviation −60 mm). That is the intended analytic result, not a defect.

### Grading

`grading-rule-set-r1.json` is `mode: measurement-driven` with one `measurement-source` rule `grade-<key>` (`source: size-entry`) per measurement input. There is no scaling rule (the standard cannot express one); every size difference comes from the measurements through the construction below. The oracle asserts that size B is not a uniform scaling of size A.

## Construction

Pieces are drawn as seen from the outside of the garment, in millimetres, X to the right and Y up, hem at y = 0. "Left" and "right" are the wearer's sides, so the wearer's left is at +X on the front and at −X on the back. Only `d2p:line` and `d2p:bezier.cubic` curves are used; points are `d2p:point.absolute`, `d2p:point.offset` or `d2p:point.polar`. There are no constraints (`constraintStatus: solved`).

### Parameters

All values are synthetic design choices for this fixture (C = chest girth, W = waist girth, S = shoulder width, A = arm length, N = neck girth, B = back length).

| Parameter | Expression |
|---|---|
| `bust-ease` | 100 mm (r2: 120 mm) |
| `sleeve-length` | 0.33 × A (r2: 0.33 × A + 30 mm) |
| `body-length` (high shoulder point to hem) | B + 260 mm |
| `quarter-chest` | (C + `bust-ease`) / 4 |
| `quarter-hem` | (max(C, W) + `bust-ease`) / 4 |
| `neck-half-width` | N / 6 + 10 mm |
| `front-neck-depth`, `back-neck-depth` | N / 4; 20 mm |
| `half-shoulder` | S / 2 + 10 mm |
| `shoulder-drop` | 45 mm |
| `armhole-depth` (high shoulder point to underarm level) | C / 8 + 130 mm |
| `armhole-height` | `armhole-depth` − `shoulder-drop` |
| `front-armhole-scoop`, `back-armhole-scoop` | 0.18 × `quarter-chest`; 0.12 × `quarter-chest` |
| `front-armhole-hollow`, `back-armhole-hollow` | 12 mm; 6 mm |
| `cap-ease-front`, `cap-ease-back` | 6 mm; 8 mm |
| `front-armhole-length`, `back-armhole-length` | arc length of `front-armhole-left-curve` / `back-armhole-left-curve` (`featureOutput … length`) |
| `cap-height` | 0.45 × `armhole-height` |
| `cap-half-width` | 0.9 × √(`armhole-length-mean`² − `cap-height`²) |
| `cap-scale-front`, `cap-scale-back` | (armhole length + cap ease) / arc length of the cap prototype |
| `sleeve-taper-angle` | 0.06 rad |
| `underarm-length` | (`sleeve-length` − `cap-height` × `cap-scale-mean`) / cos(`sleeve-taper-angle`) |
| `seam-allowance` | 10 mm (declared on every piece; not part of the v1 expected results) |

### Front and back

Both body pieces are full pieces (not cut on the fold) with the same widths, so the side and shoulder seams match by construction.

- **Hem**: a line from (−`quarter-hem`, 0) to (+`quarter-hem`, 0).
- **Side seams**: lines from the hem corners to the underarm points (±`quarter-chest`, `body-length` − `armhole-depth`).
- **Armholes**: cubic Béziers from the underarm point to the shoulder point (±`half-shoulder`, `body-length` − `shoulder-drop`). The first handle runs horizontally inwards by the armhole scoop; the second sits the armhole hollow inwards of the shoulder point and 50 % (front) or 55 % (back) of `armhole-height` below it. The front armhole is scooped deeper than the back armhole.
- **Shoulder seams**: lines from the shoulder point to the high shoulder point (±`neck-half-width`, `body-length`).
- **Neckline**: one symmetric cubic Bézier between the high shoulder points with both handles vertically below them by 4/3 of the neck depth, so the neckline passes through the centre at exactly the neck depth (front `front-neck-depth`, back `back-neck-depth`).
- Edges are listed counter-clockwise from the hem (catalog §4.2). Right-hand curves are traversed with `reversed: true`.

### Sleeve (one piece, cut as `sleeve-left` and mirrored `sleeve-right`)

- The cap apex is at (0, `sleeve-length`); it joins the shoulder seam. The back half of the sleeve is at +X.
- Each cap half is a cubic Bézier. A **prototype** cap half (construction features `sleeve-cap-*-proto-*`, never part of a contour) is drawn from the nominal `cap-half-width` and `cap-height`. The real cap half is the prototype scaled about the apex by `cap-scale-front` / `cap-scale-back`. A similarity scales arc length exactly, so **cap length = armhole length + cap ease** holds for every size and for the change case without a solver.
- The hem corners are polar points from the cap corners: the same `underarm-length` on both sides and a mirrored inward taper of 0.06 rad. Both underarm seams therefore have exactly the same length. Because the front and back caps scale slightly differently, the sleeve hem line is not exactly horizontal (about ±1 mm).
- The sleeve hem is a line between the hem corners.

### Notches and grainlines

| Notch | Edge | Position (normalized arc length along the edge direction) | Marks |
|---|---|---:|---:|
| `front-armhole-left-notch` / `-right-notch` | front armholes | 0.4 / 0.6 (40 % from the underarm) | 1 |
| `back-armhole-left-notch` / `-right-notch` | back armholes | 0.55 / 0.45 (45 % from the underarm) | 2 |
| `sleeve-cap-front-notch` | `sleeve-cap-front` | 0.6 (40 % from the corner) | 1 |
| `sleeve-cap-back-notch` | `sleeve-cap-back` | 0.45 (45 % from the corner) | 2 |

The armhole seam connections pair these notches as `matchPoints`; the cap ease is distributed proportionally between them. Grainlines run vertically along the centre line of each piece.

### Seams

| Connection (side A ↔ side B) | Ease | Length rule |
|---|---|---|
| `seam-shoulder-<side>` (front ↔ back) | none | A = B (identical lines) |
| `seam-side-<side>` (front ↔ back) | none | A = B (identical lines) |
| `seam-armhole-front-<side>` (front armhole ↔ cap front) | `eased`, amount −`cap-ease-front` = −6 mm | A − B = −6 mm |
| `seam-armhole-back-<side>` (back armhole ↔ cap back) | `eased`, amount −`cap-ease-back` = −8 mm | A − B = −8 mm |
| `seam-underarm-<side>` (underarm front ↔ underarm back) | none | A = B (same polar distance) |

`ease.amount` is the expected length of side A minus side B, so a cap that is longer than its armhole has a negative amount. All seam deviations (`lengthA − lengthB − declaredEase`) are 0 within the numeric precision below, well inside the provisional relative tolerance of 0.5 %. The sewing groups `group-armhole-<side>` (`d2p:composite-assembly`, connected) join the front and back armhole seams of each side.

## Expected results

- **Control points**: in each snapshot, the contour `start`, every segment `end` and the cubic `control1`/`control2` points, written in contour order per catalog §3.4 (reversed edges swap their controls). Notch points and tangent angles, grainline end points, exact bounding boxes (curve extrema, not the control polygon) and areas (Green's theorem, closed form) are included.
- **Seam pairings**: `interfaces[].lengthMm` and `seams[]` (lengths of sides A and B, declared ease, deviation) per size and configuration.
- **Garment measurements**: `measurements` of the r1 evaluations (one per applicable garment target) and the fit reports. The garment chest girth is the sum of the front and back widths at underarm level; the garment sleeve length runs from the cap apex down the vertical to the hem edge.
- **Change case** (`inputs/change/command.json`, `manifest.changeCase`): `bust-ease` +20 mm and `sleeve-length` +30 mm. Pattern r2 keeps every element ID of r1 (asserted), gets a new content digest, and its snapshots get new geometry digests; the r2 revision record has `parentRevisionIds: [r1]`, `sequence: 2`, the command's `commandId` and no `lineage`.
- **Export**: per size (regular-woven) an ExportScene2D with front, back, `sleeve-left` and the mirrored `sleeve-right`, laid out left to right with 20 mm gaps, net pattern (`seamAllowancePolicy: none`), and a PrintJobSpec for `d2p:home-print-a4`: ISO A4 portrait, 10 mm margins (stated device assumption), tiled with 10 mm overlap, registration marks and sheet labels, `scale: 1`, `calibration: {controlSquareMm: 100, placement: every-sheet}`, print notice to print at 100 %, conformance level `geometry`. Size A covers 11 × 3 sheets, size B 12 × 3 sheets. A control square is placed on the sheet itself only where the sheet has a free 100 × 100 mm position that crosses no cut line, marker or label (catalog §3.7, placement of sheet furniture). Every size-A sheet has one; size-B sheet A4 has none, so a renderer prints that sheet's control square on the appended `INFO` sheet. The print job documents do not record placement positions; this is a property of the `print` conformance level, which the 1.0 runners do not check.
- **Validation**: all reports have no findings (`result: pass`); both `export-1to1` gates decide `allow` with no reason codes.

### Numeric precision

- Arc lengths of cubic Béziers: adaptive Gauss-Kronrod G7/K15 quadrature of |B′(t)|; a subinterval is accepted when |K15 − G7| ≤ 1e-12 mm × its parameter width, so the estimated error per curve is at most 1e-12 mm.
- Points at a given arc length (notches): bisection on the parameter to binary64 resolution.
- Every number written to a derived document is quantized per d2p-c14n-v1 (half-to-even, 9 fractional digits, 1 pm). Digests follow d2p-digest-v1; the oracle verifies the catalog's test vectors before it runs.
- Expected files omit `evaluator.precision` and use `engineId: "golden-fixture"` and the reserved evaluator profile `d2p:golden-fixture-analytic` `1.0.0` (catalog §4.2).

## Negative fixtures

Each `negative/<name>/` holds only the changed documents (digests recomputed) and `case.json`, a `d2p:conformance-case` that lists the subjects, the resolution context and the expected outcome and diagnostic. `case.json` uses repository-relative paths; a byte-identical copy is part of the conformance suite at `conformance/<level>/golden-tshirt/<name>.case.json`, and `npm test` checks that the runner reports exactly the expected code.

## Assumptions and known limitations

- All values are synthetic. The construction is deliberately simple (no darts, straight side seams, one-piece cubic necklines) and has not been reviewed by a pattern maker or seamstress (QEV-016 pending).
- **Neck opening too small for a woven pull-over.** The garment has no neck opening, placket or closure, and the finished neckline (front plus back neckline arc) is only about 418 mm in size A and 447 mm in size B (`neck-half-width` = N / 6 + 10 mm, `front-neck-depth` = N / 4, `back-neck-depth` = 20 mm). That is far below an adult head circumference, so the `regular-woven` configuration could not be put on as sewn, and even a knit would be very tight. The geometry is a test object for the standard, not a wearable garment; QEV-016 reviewers should treat the neckline as a known simplification, not as a drafting proposal.
- **Shoulder-seam corners are not squared.** The neckline handles run straight down and the armhole's second handle is almost vertical, so the curves do not meet the sloped shoulder line at about 90°. At the high shoulder point the neckline meets the shoulder seam at 73.1° on front and back in size A (74.6° in size B), which gives a V-shaped peak in the joined neckline of about 34° in size A (about 31° in size B). At the shoulder point the armhole meets it at 100.0° (front) and 103.8° (back) in size A (99.0° and 102.5° in size B), a kink in the joined armhole of about 24° in size A (about 22° in size B). Drafting practice squares these corners. The angles depend on the size; pattern r2 has the same angles at the shoulder seam as r1 in each size.
- **Sleeve underarm corners are not squared.** At the sleeve's underarm corners the cap meets the underarm seam at 96.2° (front) and 94.9° (back) in size A and at 96.1° and 94.8° in size B (r2: 96.1° / 94.8° in size A, 96.0° / 94.7° in size B), measured between the end tangents of the curves in the snapshots. The joined sleeve underarm therefore has a peak of about 11° where the body's underarm corners are 90° and meet without a kink. Drafting practice squares these corners as well.
- **Front armhole longer than back armhole.** Front and back have identical widths and end points and differ only in the armhole scoop (0.18 versus 0.12 × `quarter-chest`). As a consequence the front armhole is longer than the back armhole in every case (size A 218.46 versus 212.52 mm, size B 237.00 versus 230.60 mm), and so is the front sleeve cap (size A 224.46 versus 220.52 mm). In common drafting the back armhole and the back cap are the longer ones.
- Changing any of these simplifications changes generated geometry and therefore requires a new fixture version (catalog §4).
- The tolerance profile is provisional; its values are proposals, not adopted product norms. The fixture is built so that its own seam deviations are 0, independent of the tolerance values.
- Seam allowances are declared (10 mm) but their offsets are not part of the v1 expected results (catalog §5, known deviation).
- Material/fit configurations do not change the geometry under standard 1.0 (see above).
- Notch markers in the export scenes carry two points (on the cut line and 6 mm inwards); the mark count is in the pattern, not in the scene.
- This README is hand-written and has no `documentType`, so it cannot be listed in `manifest.files`. It therefore lives outside the fixture directory `v1/`, where catalog §2.4 (D2P-REF-012) allows no unlisted file.
