# fixtures/

Golden fixtures: complete, synthetic end-to-end scenarios that implementations are tested against.

```text
fixtures/golden-tshirt/README.md   # construction, assumptions and open review (hand-written, outside the fixture directory)
fixtures/golden-tshirt/v1/
  inputs/        # project, artifacts, revisions, pattern, grading rules, size system, fit profiles, garment spec, evaluation requests, change command
  expected/      # evaluations, geometry snapshots, fit and validation reports, gates, export scenes, print jobs, change-case results
  negative/      # one directory per negative fixture: the defective documents plus case.json with the expected diagnostic
  manifest.json  # every file with role, documentType and digest; external files; configurations; change case; review state
fixtures/golden-tshirt-3d/README.md   # the 3D fixture: garments, scene inputs, expected scene structure (hand-written)
fixtures/golden-tshirt-3d/v1/          # generated by tools/oracle/golden-tshirt-3d.mjs (catalog §4.5)
```

Every file inside `v1/` is generated and listed in `manifest.json`; catalog §2.4 (D2P-REF-012) allows no unlisted file in a fixture directory, which is why the description lives one level up.

The *Golden T-Shirt* (two sizes, two material/fit configurations, front and back piece, one sleeve cut twice, change case) is the reference object across geometry, export and test suites. Its content is generated by the reference oracle `tools/oracle/golden-tshirt.mjs` (`npm run oracle`); `npm run oracle:check` (part of `npm run check`) fails on any drift and validates every file against the schema of its `documentType`. All values are synthetic test data, and the domain review (QEV-016) is pending; see [golden-tshirt/README.md](golden-tshirt/README.md).

## Fixtures in the conformance suite

- **Verify before comparing (test QEV-001).** `npm run fixture:verify` checks the manifest: every listed file exists with a matching `d2p-digest-v1` digest, there is no unlisted file, `fixtureDigest` matches, and the expanded bundle is structurally valid and resolves. A fixture that fails is **refused**; an implementation must not be compared against it. Library users call `openFixtureForComparison` from `tools/lib/fixture.mjs`, which throws instead of returning altered expected results.
- **Every fixture file is valid.** `conformance/referential/golden-tshirt/manifest-integrity.case.json` and `conformance/semantic/golden-tshirt/fixture.case.json` run all three levels on all `input` and `expected` files plus the external files; `npm test` requires that they report no diagnostic at all.
- **Every negative fixture is detected.** Each `negative/<name>/` has a conformance case in `conformance/<level>/golden-tshirt/<name>.case.json`; the runner must report exactly its expected diagnostic code (catalog §4.3).
- **Independent parsing (test OSS-001).** All fixture documents are readable with a generic JSON Schema 2020-12 validator and the published schemas, without any implementation of the standard.

Expected results are compared using the pinned profile from `tolerance-profiles/` (currently provisional). Tolerances are never adjusted after the fact to match an implementation.
