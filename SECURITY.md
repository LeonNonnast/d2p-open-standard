# Security Policy

## Supported versions

Until `1.0.0`, only the latest release and the `main` branch receive fixes.

## Reporting a vulnerability

Please **do not** open a public issue for security problems.

Report vulnerabilities privately through GitHub's [private vulnerability reporting](https://github.com/LeonNonnast/d2p-open-standard/security/advisories/new). Include a description, affected files or versions, and steps to reproduce.

You can expect an acknowledgement within 7 days. Confirmed issues are fixed in a patch release and disclosed in a GitHub Security Advisory once a fix is available.

## Scope

Relevant reports include, for example: schemas or tooling that allow resource exhaustion (e.g. pathological `$ref` or regex patterns), vulnerable dependencies of the tooling, and accidentally published sensitive data in fixtures.
